# 獎勵呈現

獎勵從哪裡出來、落在哪裡，以及玩家什麼時候被告知拿到了什麼。

## 公布

獎勵揭曉時，玩家會得到一個標題、一個升級音效與一陣粒子。它在**每一種動畫的真正
揭曉點**觸發——運鏡演出裡物品定格成真正獎勵的那一刻、原地家族裡輪盤停下的那一刻、
GUI 轉盤裡指針定住的那一刻。

```yaml
cinematic:
  reward-title: true        # false 關掉標題
  reward-title-delay: 10    # 定格後再等幾 tick
```

`reward-title-delay` 讓收尾的小跳先落定，文字才出現。想讓演出先喘一口氣就調大。

把 `reward-title` 關掉只會讓標題消失，音效與粒子照放——這個開關是針對**文字**的。
文案在你的語言檔裡（`cinematic.reward-title` 與 `cinematic.reward-subtitle`），
兩者都可以用 `%crate%` 與 `%reward%`。

{% hint style="info" %}
這就是公布**不做成時間軸任務**的原因：任務在從開箱起點起算的固定偏移觸發，而獎勵
是照自己的時程抵達的。做成內建之後，它不可能對一個還在轉的輪盤爆雷。
{% endhint %}

## 獎勵從哪裡出來

```yaml
cinematic:
  reward-anchor: crate         # crate(預設)| player
  reward-offset: '0,1.2,0'     # x, y, z
  reward-velocity: '0,0.28,0.12'
```

`reward-offset` 是**彈出點**——物品誕生的地方。它**無法瞄準**物品。

它所在的座標系取決於動畫：

| 動畫 | 座標系 |
| --- | --- |
| `cinematic` | 世界軸，從 `model-location` 起算 |
| 原地家族 | **箱子自己的座標系**：x = 右、y = 上、z = 前 |

`reward-anchor: player` 把座標系換成觀看者——放置點上是開箱的玩家，運鏡房裡則是
相機。用它的話，「玩家正前方」就只是 `0,1.0,1.5`。

原地家族的預設值是 `0,1.1,0.75`。把 z 設成 `0` 會讓獎勵出現在箱子模型內部，大一點
的模型會直接把它吞掉——如果物品看起來像掉在原地，原因就是那個 z。

`reward-velocity` 的 **y** 值決定弧線高度，連帶決定物品滯空多久。想讓開箱更俐落
就把它調小。

## 落在哪裡(僅 cinematic)

```yaml
cinematic:
  reward-target: '0,0,1.2'     # x = 右、y 不用、z = 前
```

這才是**瞄準**獎勵的鍵，而且它是在**相機的座標系**裡度量的——所以不管箱子擺成什麼
角度都不需要算數學。`0,0,1.2` 的意思是「相機正前方 1.2 格」，無論相機面向哪邊。

沒有 `reward-target` 時，水平速度就是 `reward-velocity` 說的那個值：一個沿著世界軸
的固定推力，它不知道箱子的朝向，也不知道相機在哪。斜放的箱子因此不管你怎麼調
offset，獎勵都會飛出鏡頭之外。

設了之後，速度會從彈出點反解到落點，所以拋擲會自動貼合「箱子 → 相機」那條線。

在有運鏡路徑的箱子上，瞄準用的是獎勵**落地那一刻**的相機姿態，而不是彈出那一刻的
——相機在飛行期間還在移動，對著起點瞄準會把獎勵丟到演出早已離開的地方。

原地家族**忽略** `reward-target`；每種樣式有自己的軌跡。

## 獎勵何時出現

```yaml
cinematic:
  reward-delay: 70     # 開箱後幾 tick
```

每種動畫都用同樣的方式讀它：運鏡版在這個 tick 把物品彈出，原地家族則在這時開始
演出。模型自己的開箱動畫在這之前先播。

把 `reward-delay` 推到 `length-ticks` 之後，獎勵演出就永遠沒機會執行——兩個要一起
調大。

## 兩個值得知道的坑

**縮排。** `reward-anchor`、`reward-offset`、`reward-target` 與其餘那些鍵都屬於
`cinematic:` **內部**，縮排兩個空格。把註解解開到第 0 欄會變成頂層鍵而被靜默忽略
——那時候你怎麼調它都不會有反應。

**轉錯旋鈕。** 如果獎勵沒有飛向相機，`reward-offset` 不是解法。它決定物品在哪裡
誕生；`reward-target` 才是瞄準用的。
