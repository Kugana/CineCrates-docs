# 重抽

動畫結束後、獎勵交付之前，可以讓玩家付費再抽一次。

```yaml
reroll:
  enabled: true
  max: 1
  price:
    type: money       # money | free | key
    amount: 500
```

## 它的行為

* 重抽**保證換到跟原本不同的獎勵**。它不是一次可能抽回同樣東西的重新抽取。
* 它**不會**重新檢查冷卻或每日上限，因為那仍然是同一次開箱。
* 離開介面的每一種方式——領取獎勵、關閉視窗、登出、伺服器重啟——都會領走**當下
  的那個獎勵**。花掉的鑰匙不可能什麼都沒有。
* `max` 限制一次開箱最多能重抽幾次。

## 兩條決定有沒有人用它的規則

**價格要低於一把鑰匙。** 如果重抽要花一把完整的鑰匙，那再開一次嚴格來說更划算：
玩家會得到另一段動畫、另一次保底計數、以及對所有獎勵的另一次機會，而不只是替換。
用金錢或免費才會讓它有吸引力。

**重抽會放棄保底獎。** 這是刻意的。保底的存在是為了讓一連串的壞運氣以保證作結；
如果玩家能重抽掉保底獎又保留計數，那個保證就變成可有可無的。

## 什麼時候不會出現介面

一次開出多件獎勵的箱子會**完全跳過**重抽介面——`rewards-per-open` 大於 1，或是
加權表剛好抽到多於一件時。「這三件我要重抽哪一件？」是個複雜度遠高於其價值的
介面，而整組重抽又會讓夾在其中的保底獎消失。

想在箱子上使用重抽，就讓它維持一次一件：

```yaml
rewards-per-open: 1
reroll:
  enabled: true
```

## 獎勵公布

公布獎勵名稱的標題會**跟著重抽走**：玩家被告知的是他實際拿到的東西，不是動畫
剛好展示過、後來被重抽掉的那個。見[獎勵呈現](../animations/reward-presentation.md)。
